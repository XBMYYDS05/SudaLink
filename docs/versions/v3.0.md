# 3.0.0 · 改名 SudaLink，修好热点，界面重构

一次改了三件大事：全量改名、修一个"以为能用其实从来没生效"的功能、把四页压成三页。

## 全量改名

`CampusNet` → `SudaLink`，改的不只是标题：

| 位置 | 值 |
| --- | --- |
| 命名空间 / 程序集 / 进程名 | `SudaLink` |
| 配置文件 | `sudalink.json` |
| 注册表启动项 | `HKCU\...\Run` 下的 `SudaLink` |
| 单实例互斥体 | `Local\SudaLink.SingleInstance` |
| 激活事件 | `Local\SudaLink.Activate` |

改名最容易漏的是**存量数据**：`ConfigStore` 要能读旧的 `campusnet.json`，`AutoStartService`
要顺手删掉旧的 `CampusNetWpf` 启动项，否则用户机器上会同时躺着两条开机启动。

## 热点：一个"返回成功但什么都没做"的 bug

旧实现是用 PowerShell 调 WinRT 的 `NetworkOperatorTetheringManager`：

```powershell
$mgr.StartTetheringAsync()   # ← 这里返回的是 IAsyncOperation，没有被 await
```

PowerShell 把 `IAsyncOperation` 当成一个普通对象丢掉了，**请求压根没发出去**，
脚本还正常退出。所以现象是"点了没反应，也不报错"。

改法：TFM 提到 `net8.0-windows10.0.19041.0`，直接用 CsWinRT 调：

```csharp
var result = await manager.StartTetheringAsync().AsTask();
```

第一次真开成功时日志打出"热点已开启，0 台设备已连接"——那一行是整个项目最解气的一行输出。

## 运营商选择器

原来要在学号后面手打 `@zgyd` / `@cucc` / `@ctc`，属于把实现细节漏给了用户。
改成四段选择（校园网 / 移动 / 联通 / 电信），内部仍然拼后缀，但 `Account` 上暴露的是
`Number` + `CarrierName`，序列化时只存语义名。

## 界面

- 四页（概览 / 账号 / 设置 / 日志）压成三页，日志并进概览。
- 侧栏 180px，苏大红 `#A6192E` 作主色，卡片 12px 圆角。
- 颜色集中到 `Theme.xaml`，为后面换主题埋路。
- 设置项改动即存，只有网关保留"应用"按钮（它需要校验格式）。
- 在线时不再反复刷"正在检测"，避免状态抖动。

## 教训

> **"调用成功"和"事情发生了"是两件事。**
> 涉及异步 API 时，必须验证副作用（热点真的开了、文件真的写了），而不是看返回值。
