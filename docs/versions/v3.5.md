# 3.5.0 · 真磨砂 + 深浅双主题

两个目标：玻璃要真的"透过它看背景"，以及**深色 / 浅色双主题**。

## GlassPanel 加 Backdrop

新增 `Backdrop`（Visual DP）+ `FrostRadius`：模板里的 `PART_Frost` 用
`VisualBrush` 按面板自身在背景中的矩形取 `Viewbox`，外面套 `BlurEffect`。
位置靠 `TransformToVisual(Backdrop)` 在 `LayoutUpdated` 里算，Viewbox 带 0.5px 容差防死循环。

**关键认知**：模糊要有东西可模。背景必须加高频细节 —— 铺了一层 128px 噪点矩形
（`Opacity 0.20`），否则纯净渐变模糊前后没差别。噪点太重会整屏发脏（试过 0.55，太脏）。

**玻璃该提亮不该压暗**：染色层从深色 `#0A0F1C` 改成白 `#0AFFFFFF`。
真实玻璃反射环境光，会略微提亮背后的内容。

## 双主题架构

`Themes/Palette.Dark.xaml` / `Palette.Light.xaml`，各 60+ 个 key。
`Theme.xaml` 与 `MainWindow.xaml` 的颜色引用全部改成 `DynamicResource`，
`ThemeService.Apply()` 替换字典即可实时切换。设置页有「外观：深色 / 浅色」，默认 **Light**。

## 三个致命坑

### 1. `GradientStop.Color` 只吃 `Color`

往里塞 `SolidColorBrush` 不会报设计期错误，而是让**渲染通道崩**：
弹错误框 + 窗口塌成 649×251（`UCEERR_MISSINGENDCOMMAND`）。

所以渐变用 `*Color` 资源，`Background` / `Fill` 用 Brush 资源，同名要拆成两个 key：
`TabFillA` / `TabFillAColor`。**同一色值在不同属性上是不同类型，不能共用一个 key。**

### 2. `MergedDictionaries` 里同一个 key 出现两次

`App.xaml` 预置一份色板 + `ThemeService` 又插一份 → 主题切换"看起来没生效"。
改成 `App.xaml` 只合并 `Theme.xaml`，色板由 `ThemeService` 独家管理、替换式安装。

### 3. `WindowChrome` + `GlassFrameThickness="-1"`

当 `Window.Background` 是 `DynamicResource` 时，会在 `_ExtendGlassFrame` 里崩。
自绘方案本来就不需要系统玻璃框：改 `GlassFrameThickness="0"`、窗口底色写死
（被 Backdrop 完全覆盖）。

## 结构上的一个细节

`ThemeService` 必须放在 `src/SudaLink/`（不是 `Core/`），
否则测试工程的 `Compile Include="Core\**"` 会把 WPF 依赖拖进纯逻辑测试。

## 结果

玻璃"看起来"透了，但**其实没有** —— 根因要到 3.6 才找到。
