# 3.6.0 · 找到磨砂一直没生效的根因

用户第三次说玻璃不对：**「这个玻璃的效果还是没有实现，感觉颜色还是很脏不透」**。
这次不再调参数，先验证"玻璃里到底有没有背景"。

## 根因

3.5 的实现是：

```csharp
// OnLoaded 里同步执行
var rtb = new RenderTargetBitmap(...);
rtb.Render(Backdrop);          // ← 此刻壁纸 Image 还没绘制完成
_cache = rtb;                  // ← 拿到一张全透明位图
_dirty = false;                // ← 标记为"已缓存干净"，于是再也不重渲
```

两个错误叠在一起：

1. `RenderTargetBitmap.Render()` 对**尚未绘制**的视觉元素返回的是空白位图，不报错。
2. 缓存标记在渲染之后置位，导致空白位图被永久使用。

结果：玻璃层一直是一张**空画刷** —— 项目里从来没有真的模糊过。
之前所有"看起来糊了"的错觉，都来自壁纸自带的柔光。

## 改法：删掉 RTB，改解析式取样

背景只有一张 `Image`（`Stretch=UniformToFill`），所以可以不渲染、直接**算**：

```csharp
scale  = max(areaW / imgW, areaH / imgH);
origin = (area - img * scale) / 2;
viewbox = (pane - origin) / scale;     // pane = 面板矩形外扩 Bleed
```

拿到的 `ImageBrush(ViewboxUnits=Absolute, Viewbox=…)` 再套 `BlurEffect`：
1:1、全分辨率、**没有任何时序问题**。

刷新时机：`LayoutUpdated` 里做增量判断（矩形差 < 0.35 跳过）；
`InvalidateBackdrop()` 里立刻试一次，再在 `DispatcherPriority.Loaded` 补一次，
避免布局未完成时算错。

边缘：模糊会吃边，取样区外扩 `Bleed = ceil(blur * 2.2) + 6`，`PART_Frost.Margin = -Bleed`，
外层 Grid 用圆角 `Clip` 裁掉。折射用 `Refraction = 0.968`（取样范围收 3.2%，
画面被轻微放大 = 厚玻璃的透镜感）。

## 第二个元凶：镜面高光

静态时镜面高光停在默认位置，那个白色椭圆把卡片顶部**烧成纯白**（实测 253,253,254）。
"不透"的感觉有一半来自它。改成**只在指针进入时浮现**，静态 `Opacity = 0`。

## 第三个元凶：壁纸色相跨太大

模糊会把**互补色平均成灰色**。一屏从蓝跨到玫红，玻璃里必然是脏灰 —— 这是"脏"的
物理来源，不是调透明度能救的。所以壁纸改成**纵向相近色相坡道**，
细节只用**白色丝带**（无彩，模糊后只变软、不串色）和颗粒。

## 顺便修掉的三个真 bug

1. 切主题后玻璃仍用旧壁纸（`DynamicResource` 换图有时序差）→ `ApplyBackdrop()` 改用
   `BitmapCacheOption.OnLoad` 同步设 `Source`。
2. 载入设置时 `RadioButton` 的 `Click` 把主题改回浅色 → 加 `_loadingSettings` 守卫。
3. `Margin="0,2,9"` 是非法值（三值 Margin 不存在）→ 启动即崩。

## 新增

`--theme=dark|light` 启动参数（截图 / 验证用，不落盘）。

## 结果

玻璃终于是真的了：卡片内的色相与卡片外的色相一致，只是被磨掉了细节。
窗口 440×618，圆角 26，6/6 测试通过。

但截图里整体还是一层发闷的奶白 → 4.0 继续。
