# 3.2.0 · 修掉左上角的割裂感，状态按钮红绿分明

## 左上角为什么"割裂"

原来的布局是：标题栏横跨整个窗口（38px 高、深色），左列白色侧栏从标题栏**下方**才开始。
于是窗口左上角有一块小而突兀的横带：上面是深色，左下是白色，中间没有过渡，
视觉上像两张纸没对齐。

改法不是"修补那块横带"，而是**换布局结构**：整窗两列，左列白色侧栏**通高**（包含标题区），
右列自己画最小化 / 最大化 / 关闭。品牌行（校徽 + 名字）与右侧窗口按钮在同一高度对齐，
左侧就成了一条连续的白柱。

> 视觉缺陷如果来自结构，就改结构。在错的骨架上做渐变、加描边，只会把错的地方弄得更明显。

## 状态胶囊：开绿关红

要求很具体：暂停重连与热点开关，**开启时绿色，关闭时红色**。

`Theme.xaml` 里抽出 `StateGhost` 基样式，派生两个：

| 样式 | 背景 | 描边 | 文字 |
| --- | --- | --- | --- |
| `GhostOn` | `#F0FAF5` | `#BFE6D3` | `#0A7F58` |
| `GhostOff` | `#FDF3F4` | `#F2CBD1` | `#B4232F` |

hover / pressed 用半透明黑叠层，不换基色 —— 一旦换基色，红绿语义就被破坏。

胶囊里是"圆点 + 文案"，**圆点填充绑定 `Button.Foreground`**，于是颜色随状态自动走，
不用在两个地方各写一次颜色。

## 热点从"只能开"改成开关

热点服务补了 `IsOnAsync()` / `TurnOffAsync()` / `StateChanged` 事件：

```
isOn → TurnOff（事件 false）→ EnsureOn（事件 true）
```

用独立控制台探针 `.workbuddy/tools/hotspot-probe` 跑通这个闭环之后才接的 UI。
监控器自动开热点时也会 `Raise(true)`，所以胶囊颜色会跟着变，不需要 UI 层再判断一次。

## 其他

- 窗口再压到 **740×492**（Min 690×460）。
- 设置页实测 `ScrollableHeight=0`，不需要滚动条。
- 暂停态文案改成「已停止自动检测，点击「立即连接」可手动重试」，不再和标题重复。

## 教训（验收方法）

这个环境里 `mouse_event` / `PostMessage` 注入点击不可靠（悬停生效、Click 不触发），
窗口还会因为残留实例被截错。可靠的验收方式是**在应用里加一个临时 `--uitest` 分支**，
用 `RenderTargetBitmap` 直接渲染 `this` 存 PNG —— 拿到的是真实渲染结果，不受前台窗口影响。

这条经验在 4.0 里被固化成了正式的 `--render=` 参数。
