# 4.3.0 · 修圆角阴影 + 配置固定不丢账号

## 两个问题

### 1. 账号页 / 设置页「圆角处理有问题，不知道哪里来的阴影」

排查下来是两个独立的东西叠加：

**a) 内容层没有圆角裁剪。** `GlassPanel` 模板里，只有磨砂层（`PART_Clip`）有圆角
`Clip`，染色层、受光层、**内容层（ContentPresenter）** 都没裁。账号列表的选中
高亮、输入框、分段选择器贴着卡片边缘时，会在 26px 圆角处露出方角，观感就是
"圆角没处理好"。

**b) 投影太重 + 壁纸左下冷色光晕。** 浅色 `PanelShadow` 是 `BlurRadius=26 / Depth=6 /
Opacity=0.22`，在极简浅色背景上投影显得"脏"；再加壁纸左下角那抹 `#BCCFE8` 冷色光晕
从卡片间隙透出来，被误认成阴影。

### 2. 账号配置分散，导致"老是重新添加账号"

`ConfigStore` 默认路径是 `AppContext.BaseDirectory`（exe 所在目录）。于是：

| 运行位置 | 读到的配置 |
| --- | --- |
| `D:/SUDANET/SudaLink.exe` | `D:/SUDANET/sudalink.json`（3 个账号） |
| `D:/SUDANET/dist/SudaLink.exe` | `D:/SUDANET/dist/sudalink.json`（空） |

用户之前从 dist 运行过，账号就"丢"了。根因是配置跟着 exe 位置走，而不是固定在一个地方。

## 修改

### 圆角与阴影

- **GlassPanel 模板重构**：把圆角裁剪从"只裁磨砂层"改成"外层 `Border` 带
  `CornerRadius` + `ClipToBounds` 统一裁掉所有子层（磨砂 / 染色 / 受光 / 内容）"。
  删掉了 `PART_Clip` 和 `ApplyClip()` 里针对磨砂层的单独裁剪逻辑。
- **投影收敛**：`PanelShadow` `26/6/0.22` → `18/3/0.14`，`FloatShadow` 同步，
  颜色 `#12203A` → `#0B1220`。投影不再是一圈明显的暗边。
- **壁纸**：删掉左下角冷色光晕（`plain` 风格下 `vig` 降到 0.04）。
- **窗口加高**：618 → 660（Min 560 不变）。账号页「列表卡片 + 完整表单卡片」在 618 高
  下必然溢出触发滚动条，660 给它留出呼吸空间。
- **账号页垂直节奏收紧**：账号列表 `MaxHeight` 136 → 80，列表项行距 9 → 7，
  表单卡片底部 padding 10 → 6，几处 margin 各减 1~2px。结果是账号页和设置页
  **都不再出现滚动条**。

### 配置固定

- 把根目录的完整配置（3 个账号，DPAPI 加密密码）复制到 `dist/sudalink.json`。
- 旧明文 `accounts.txt` / `current.txt` / `settings.txt` 备份到
  `.workbuddy/archive/legacy-plaintext/` 后从根目录移除（它们是反编译遗留的明文密码，
  既有泄露风险，也会干扰 `ConfigStore` 的旧格式 fallback）。

## 验证

- 单元测试 7/7 通过。
- 从 `dist/SudaLink.exe` 渲染账号页，确认读到了 3 个账号（学号文字齐全，无空态提示）。
- 像素检查：卡片内亮度 249 vs 背景 243，差异 6 个单位，投影已收敛；
  账号页 / 设置页右侧无贯穿滚动条。

## 教训

> **配置文件的"家"只有一个，不能跟着 exe 走。**
> 单文件发布后 exe 会被复制到各种目录（下载、桌面、dist），
> 配置如果放在 exe 旁边，用户就会在不同位置看到"不同的一份账号"。
> 这里暂时统一到 exe 目录 + 把权威配置同步过去；更稳的做法是固定到
> `%APPDATA%\SudaLink\`，留作后续。
