# 2.0.0 · 反编译之后按协议重写

## 背景

手上有一个别人写好的 `CampusNet(2).exe`，能用但改不动、看不到源码。
第一步不是"自己发明一个登录流程"，而是**先把协议搞清楚**。

用 ILSpy（`ilspycmd`）把原程序完整反编译，得到两件事：

1. **协议**：直连 Dr.COM eportal，不需要浏览器自动化。
2. **配置形态**：`accounts.txt`（`用户名|密码`）、`current.txt`、`settings.txt`（key=value），全是明文。

顺手在 GitHub 上找了一圈现成方案：

- `iAllie2002/SUDA-NetTool`：Selenium 驱动浏览器，重，且要求机器上有对应浏览器。
- `1-Dot/Suda-WiFi-Helper`：Python，监听 WiFi 事件再触发登录。
- `HolgerZhang/SUDA_WIFI-autoconn`：直接打 eportal，思路与本项目一致。

结论：**直连 eportal 就够了**，浏览器自动化是多余的一层。

## 协议细节

```
GET  http://10.9.1.3/?isReback=1
     → 页面里 uid='0' 表示未登录，否则已登录

POST http://10.9.1.3:801/eportal/?c=ACSetting&a=Login
     表单 DDDDD / upass / R1=0 / R2=0 / R6=0 / para=00 / 0MKKey=
     → 成功响应含 Dr.COMWebLoginID_3
     → 失败响应含 Msg=01..09
```

`Msg` 的取值含义分散在多个学校的文档里，本项目按 `PortalAuthenticator` 里的映射给出中文提示。

## 这一版做了什么

- `net8.0-windows`，WPF + WinForms（托盘）。
- **真实联网检测**：不只看网关，还用 msftconnecttest / firefox 的探测页判断"是不是真的能上网"，
  从而区分「没网」「不在校园网」「在线」三种状态 —— 这三者的处理策略完全不同。
- **失败退避**：连续失败按指数退避，封顶 120 秒，避免把网关打烦。
- **多账号**：当前账号优先，其余按顺序轮试。
- **DPAPI 加密**：密码用 `ProtectedData`（CurrentUser 作用域）加密写进 `campusnet.json`，
  旧的明文 `accounts.txt` / `current.txt` / `settings.txt` 首次启动自动迁移并保留备份。
- 单实例 Mutex、托盘菜单、日志复制/清空。

## 教训

- 该 SDK 下 WPF+WinForms 项目的隐式 using 不含 `System.IO` / `System.Net.Http`，
  还会全局引入 `System.Drawing` 与 `System.Windows.Forms`（与 WPF 的 `Color`/`Brush` 撞名）。
  在 csproj 里用 `Using Include` / `Using Remove` 精确控制，别在文件里堆 `using` 别名。
- 迁移旧配置必须**先备份再删除**，否则用户第一次打开就丢账号，信任度直接归零。
